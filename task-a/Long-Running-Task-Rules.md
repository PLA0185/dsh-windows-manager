# Long-Running Task Rules

- 对长任务、多阶段开发、复杂调试或持续时间较长的工作，不要把多个主要阶段强行塞进单个模型轮次。
- 每完成一个明确阶段或一个实质性工作单元后，先把代码、测试结果、文档和当前进度可靠落盘，再继续下一阶段。
- 避免为了“继续工作”而无限延长单轮输出直到触发 `maxTokens`。
- 如果单轮达到输出 token 上限，下一轮必须从已经记录的进度继续，不得重新开始，不得重复已完成的调研、实现或测试。
- 阶段总结保持简洁；已经存在于仓库文件、日志或文档中的大段内容不要重复粘贴到回答中。
- 优先复用已有调研、缓存、文档和已验证结果；只有事实缺失、版本可能变化或当前证据不足时才重新查询。
- 对大型任务采用“查证 → 设计 → 实现 → 测试 → 验证 → 记录进度 → 下一阶段”的循环，不使用“先随便做 → 出错 → 连续打补丁”的方式。
- 自动化测试通过、构建通过、文件写入成功与真实功能验证必须分开汇报，不得把中间状态写成最终验证成功。
- 如果后续阶段存在明确阻塞项，只汇报真正需要用户决定的阻塞；普通技术细节应依据现有任务书、官方文档、上游仓库和测试结果自行处理。
